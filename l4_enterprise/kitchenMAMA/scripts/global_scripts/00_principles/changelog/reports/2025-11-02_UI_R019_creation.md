# UI_R019: AI Process Notification Rule - Creation Report

**Date**: 2025-11-02
**Author**: Claude (Principle Revisor)
**Type**: New Principle Creation
**Category**: UI Components Law - Rule
**Priority**: HIGH - Critical for AI-powered components

## Executive Summary

Created comprehensive new principle **UI_R019: AI Process Notification Rule** based on critical user feedback that static notification messages for long-running AI processes create perception of "broken system."

### User Feedback That Triggered This Principle

> "我覺得『Filters changed. AI analysis will be regenerated...』光是這個很難讓人覺得要等而會感覺好向壞掉了"
>
> Translation: "Just seeing 'Filters changed. AI analysis will be regenerated...' doesn't make people feel like they should wait; instead it feels like the system is broken."

**User Request**: "你可能要用...principle revisor說明AI過程都要有通知這件事情，因為蠻重要的"

Translation: "Use principle revisor to document that AI processes should have notifications, because this is quite important."

## Principle Overview

### Core Requirement

**All AI/OpenAI API processes expected to run longer than 2 seconds must provide real-time stage-based notifications** to prevent user anxiety and communicate system status effectively.

### Key Thresholds

| Duration | Notification Requirement | Implementation |
|----------|-------------------------|----------------|
| < 2 seconds | Optional | Simple spinner/loading |
| 2-10 seconds | Required | Initial notification |
| **> 10 seconds** | **Mandatory** | Multi-stage progressive notifications |
| > 30 seconds | **Mandatory** | Multi-stage with ETA/progress |

### UX Psychology Foundation

**Why This Matters:**

1. **Static messages for > 10 seconds make users think system is frozen**
2. Progressive feedback reduces perceived wait time by up to 40% (Nielsen Norman Group)
3. Known stages reduce user anxiety and build trust
4. Transparent process demonstrates professional, well-designed system

**Psychological Impact:**

```
Same 25-second operation, different user experience:

Static Notification (BAD):
[0s]  "AI analysis will be regenerated..."
[10s] ... still same message ... (user: broken?)
[20s] ... still same message ... (user: definitely broken)
[25s] Done (user: that was painful)

Progressive Notification (GOOD):
[0s]  "📊 正在提取資料..."
[2s]  "🎯 正在執行分群..." (user: oh, clustering now)
[8s]  "🏷️ 正在產生分群名稱..." (user: naming next, makes sense)
[15s] "📝 正在產生AI報告..." (user: almost done!)
[25s] "✅ 完成！" (user: fast and professional!)
```

## Implementation Requirements

### 1. Language Compliance (UI_R007)

**Traditional Chinese UI**: All notifications in Traditional Chinese
**English UI**: All notifications in English
**No mixing**: Never mix languages

```r
# ✅ CORRECT
showNotification("📊 正在提取資料...", id = "progress", duration = NULL)

# ❌ INCORRECT - violates UI_R007
showNotification("Extracting data...", id = "progress", duration = NULL)
```

**Required emoji patterns for visual clarity:**

### 3. Standard Implementation Pattern

```r
# Multi-stage AI process with progressive notifications
ai_multi_stage_analysis <- function(session, filtered_data, k_clusters) {

  # Define stage messages
  STAGE_MESSAGES <- list(
    stage1_data = "📊 正在提取資料...",
    stage2_cluster = paste0("🎯 正在執行分群 (K=", k_clusters, ")..."),
    stage3_naming = "🏷️ 正在產生分群名稱...",
    stage4_report = "📝 正在產生AI報告...",
    complete = "✅ 分析完成！"
  )

  tryCatch({
    # Stage 1: Data Extraction
    showNotification(STAGE_MESSAGES$stage1_data, id = "ai_progress", duration = NULL)
    data <- filtered_data()

    # Stage 2: Clustering
    removeNotification("ai_progress")
    showNotification(STAGE_MESSAGES$stage2_cluster, id = "ai_progress", duration = NULL)
    clusters <- perform_clustering(data, k_clusters)

    # Stage 3: AI Naming
    removeNotification("ai_progress")
    showNotification(STAGE_MESSAGES$stage3_naming, id = "ai_progress", duration = NULL)
    names <- generate_ai_cluster_names(clusters)

    # Stage 4: AI Report
    removeNotification("ai_progress")
    showNotification(STAGE_MESSAGES$stage4_report, id = "ai_progress", duration = NULL)
    report <- generate_ai_report(clusters, names)

    # Completion
    removeNotification("ai_progress")
    showNotification(STAGE_MESSAGES$complete, duration = 3, type = "message")

    return(list(clusters = clusters, names = names, report = report))

  }, error = function(e) {
    removeNotification("ai_progress")
    showNotification(paste0("❌ 分析失敗: ", e$message), duration = 5, type = "error")
    return(NULL)
  })
}
```

### 4. Filter Change Handler Pattern

```r
# Proper notification when filters trigger AI regeneration
observeEvent(c(input$filter1, input$filter2), {

  # Clear previous results
  ai_results$clusters <- NULL
  ai_results$names <- NULL
  ai_results$report <- NULL

  # Notify user
  showNotification(
    "🔄 篩選條件已變更。AI 分析將重新產生...",
    duration = 3,
    type = "warning"
  )

  # Schedule async regeneration with progressive notifications
  later::later(function() {
    new_results <- ai_multi_stage_analysis(session, filtered_data, input$k_clusters)
    ai_results$clusters <- new_results$clusters
    ai_results$names <- new_results$names
    ai_results$report <- new_results$report
  }, delay = 0.5)
}, ignoreInit = TRUE)
```

## Related Principles

### Direct Dependencies

1. **MP099: Real-Time Progress Reporting**
   - UI_R019 is the UI-specific implementation of MP099
   - MP099 covers all progress reporting (console, logs, monitoring)
   - UI_R019 focuses specifically on Shiny UI notifications

2. **UI_R007: UI Text Standardization Rule**
   - All notification text must follow UI_R007 language requirements
   - Must use `translate()` function for internationalization
   - No language mixing allowed

3. **MP052: Unidirectional Data Flow**
   - Notifications are informational only
   - Do not use notifications to trigger reactive updates
   - Notifications follow data changes, not drive them

4. **UI_R001: UI-Server-Defaults Triple Rule**
   - Notification logic belongs in Server component
   - Not in UI or Defaults components

### Manual Testing Checklist

For each migrated component:

2. **Stage Progression**: Notifications update at each stage
3. **Timing Validation**: Operations > 2s have notifications
4. **Language Consistency**: No language mixing

6. **Error Handling**: Error notification shows with details
7. **No Stacking**: Only one notification visible at a time

### Automated Testing

```r
test_that("UI_R019: AI process has progressive notifications", {
  testServer(componentServer, {
    session$setInputs(trigger_ai = TRUE)

    # Initial notification
    expect_true(notification_exists("ai_progress"))

    # Stage progression
    Sys.sleep(0.5)
    expect_match(get_notification_text("ai_progress"), "正在提取資料|Extracting data")
```
