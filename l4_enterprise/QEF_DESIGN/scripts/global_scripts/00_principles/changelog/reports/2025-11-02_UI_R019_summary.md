## Why This Principle Was Created

### User Feedback (The Trigger)

> "我覺得『Filters changed. AI analysis will be regenerated...』光是這個很難讓人覺得要等而會感覺好向壞掉了"

**Translation**: "Just seeing 'Filters changed. AI analysis will be regenerated...' doesn't make people feel like they should wait; instead it feels like the system is broken."

**User Request**: "Use principle revisor to document that AI processes should have notifications, because this is quite important."

### The Core Problem

**Static notification messages for > 10 seconds create perception of broken system**

- Users cannot tell if system is working or frozen
- After 10 seconds, users assume error occurred
- Creates anxiety, frustration, and loss of trust
- Unprofessional appearance damages brand perception

## The Solution: Progressive Stage Notifications

### Psychological Impact Comparison

**Same 25-second AI operation, dramatically different user experience:**

#### Bad: Static Notification
```
[0s]  "AI analysis will be regenerated..."
[10s] ... (user thinks: broken?)
[20s] ... (user thinks: definitely broken!)
[25s] Done (user thinks: that was painful)
```

#### Good: Progressive Notifications
```
[0s]  "📊 正在提取資料..." (Extracting data...)
[2s]  "🎯 正在執行分群..." (Clustering...)
[8s]  "🏷️ 正在產生分群名稱..." (Generating AI names...)
[15s] "📝 正在產生AI報告..." (Generating AI report...)
[25s] "✅ 完成！" (Complete!)
```

**Result**: 40% reduction in perceived wait time (Nielsen Norman Group research)

## Core Requirements

### When Notifications Are Required

| Duration | Notification Requirement |
|----------|-------------------------|
| < 2 seconds | Optional |
| 2-10 seconds | **Required** - Initial notification |
| **> 10 seconds** | **Mandatory** - Multi-stage progressive |
| > 30 seconds | **Mandatory** - Multi-stage with ETA |

### What Must Be Implemented

1. **Language Compliance**: All notifications in UI language (Traditional Chinese for Chinese UI, English for English UI)
2. **Emoji Usage**: Appropriate emoji for each process type (📊 data, 🎯 clustering, 🏷️ AI naming, 📝 AI report)
3. **Progressive Updates**: Notification changes at each stage, not static
4. **Error Handling**: Remove progress notifications, show error details
5. **Notification ID Management**: Use same ID for stage progression to avoid stacking

## Standard Implementation Pattern

```r
# Multi-stage AI process with progressive notifications
ai_multi_stage_analysis <- function(session, filtered_data, k_clusters) {

  # Define stage messages
  STAGE_MESSAGES <- list(
    stage1_data = "📊 正在提取資料...",
    stage2_cluster = paste0("🎯 正在執行分群 (K=", k_clusters, ")..."),
    stage3_naming = "🏷️ 正在產生分群名稱...",
    stage4_report = "📝 正在產生AI報告...",
    complete = "✅ 分析完成！"
  )

  tryCatch({
    # Stage 1
    showNotification(STAGE_MESSAGES$stage1_data, id = "ai_progress", duration = NULL)
    data <- filtered_data()

    # Stage 2
    removeNotification("ai_progress")
    showNotification(STAGE_MESSAGES$stage2_cluster, id = "ai_progress", duration = NULL)
    clusters <- perform_clustering(data, k_clusters)

    # Stage 3
    removeNotification("ai_progress")
    showNotification(STAGE_MESSAGES$stage3_naming, id = "ai_progress", duration = NULL)
    names <- generate_ai_cluster_names(clusters)

    # Stage 4
    removeNotification("ai_progress")
    showNotification(STAGE_MESSAGES$stage4_report, id = "ai_progress", duration = NULL)
    report <- generate_ai_report(clusters, names)

    # Completion
    removeNotification("ai_progress")
    showNotification(STAGE_MESSAGES$complete, duration = 3, type = "message")

    return(list(clusters = clusters, names = names, report = report))

  }, error = function(e) {
    removeNotification("ai_progress")
    showNotification(paste0("❌ 分析失敗: ", e$message), duration = 5, type = "error")
    return(NULL)
  })
}
```

## Common Violations to Avoid

### ❌ Violation 1: No Notification
```r
result <- call_openai_api(prompt)  # Takes 15s, no notification
```

### ❌ Violation 2: Static Notification Only
```r
showNotification("Processing...", duration = NULL)
# ... 30 seconds of processing ...
```

### ❌ Violation 3: English in Chinese UI
```r
showNotification("Generating report...", duration = NULL)  # Violates UI_R007
```

### ❌ Violation 4: Notification Stacking
```r
showNotification("Stage 1...", duration = NULL)  # No ID
showNotification("Stage 2...", duration = NULL)  # Stacks on top
```

### ❌ Violation 5: Silent Filter Changes
```r
observeEvent(input$filter, {
  regenerate_ai_analysis()  # No notification!
})
```

## Questions & Answers

### Q: How many stage notifications should I use?
**A**: Depends on duration:
- 2-5s: 1-2 stages (initial + completion)
- 5-15s: 2-3 stages (every 3-5 seconds)
- 15-30s: 3-5 stages (every 5-7 seconds)
- \>30s: 4-6 stages with ETA (every 7-10 seconds)

### Q: What if my process has 10 sub-steps?
**A**: Group related sub-steps into logical stages. Don't overwhelm users with too many updates.

### Q: Can I use progress bars instead of notifications?
**A**: Use **both**. Notifications for process stages, progress bars for percentage completion.

### Q: What about English UI applications?
**A**: Same requirements, but use English text instead of Traditional Chinese. Follow UI_R007.

### Q: Do I need notifications for operations < 2 seconds?
**A**: Optional. Use simple spinner/loading indicator. Not mandatory.

### Q: What if OpenAI API is down?
**A**: Error handling required. Remove progress notification, show error with details, duration = 5 seconds.
