## MP107 — ETL Pipeline Independence Principle

### Frontmatter snapshot

- `id: "MP107"`
- `title: "ETL Pipeline Independence Principle - CORE ARCHITECTURAL REQUIREMENT"`
- `version: "2.0"`, `priority: "CRITICAL"`
- `category: "data_management"`
- `related_to`: MP108, MP104, MP064, MP031, MP103, DM_R037, DM_R028
- Path: `00_principles/docs/en/part1_principles/CH00_fundamental_principles/04_data_management/MP107_etl_pipeline_independence.qmd`

### Classification: **in-ETL-scope**

Reasoning:

MP107 normative text directly governs ETL pipeline form:

> "Every ETL pipeline MUST be completely independent and self-contained"
> "Each ETL script is a standalone, autonomous unit"

The phrase "ETL script" assumes R script form. Under post-glue era (per amended MP064 / DM_R028 in this P1 change), 0IM phase MAY be implemented as bridge yaml. MP107 must acknowledge that "ETL pipeline" concept extends to:

1. **Legacy R script form**: existing `<platform>_ETL_<datatype>_0IM.R` + `_1ST.R` + `_2TR.R` chain
2. **Post-glue form**: bridge yaml at `bridges/<COMPANY>/<platform>/<datatype>.bridge.yaml` (replaces 0IM R script) + 1ST.R + 2TR.R chain

Both forms continue to satisfy MP107 independence (each datatype's pipeline still independent of other datatypes' pipelines). But MP107 wording assumes R-script-only form, which becomes increasingly stale as P3 migration progresses.

### Amendment scope (TBD details — to be authored in Task 6.1)

- Update normative text "ETL script" → "ETL pipeline" (encompassing both forms)
- Add subsection acknowledging bridge yaml as alternative 0IM implementation
- Clarify that independence applies at pipeline level, regardless of 0IM form
- Cross-ref `etl-architecture-roadmap` Requirement 3 (canonical at raw layer post-glue)
- Increment `version` from v2.0 to v2.1

## MP108 — ETL Phase Sequence Principle

### Frontmatter snapshot

- `id: "MP108"`
- `title: "ETL Phase Sequence Principle - Vertical Data Flow Within Pipelines"`
- `version: "1.0"`, `priority: "CRITICAL"`
- `category: "data_management"`
- `related_to`: MP107, MP109, MP104, MP102, MP064, DM_R028
- Path: `00_principles/docs/en/part1_principles/CH00_fundamental_principles/04_data_management/MP108_etl_phase_sequence.qmd`

### Classification: **in-ETL-scope**

Reasoning:

MP108 explicitly governs phase sequence "0IM → 1ST → 2TR" within base ETL pipelines:

> "Within each BASE ETL pipeline (those processing raw external data), phases must execute in their natural sequence when running the complete pipeline: 0IM → 1ST → 2TR"

Under glue era, the 0IM phase implementation can be either R script OR bridge yaml. The natural sequence still holds (raw → staged → transformed), but MP108's discussion implicitly assumes R-script-form 0IM.

Critically, MP108 references "BASE ETL pipeline (those processing raw external data)" — bridge yaml is precisely a base ETL pipeline that processes raw external data. So MP108 already covers bridge yaml conceptually, but the explicit text needs to acknowledge the dual implementation.

### Amendment scope (TBD details — to be authored in Task 6.2)

- Update phase 0IM diagram/description to acknowledge dual implementation form (R script OR bridge yaml)
- Clarify that "0IM → 1ST → 2TR" sequence applies regardless of 0IM form
- Note that under glue migration (per `etl-architecture-roadmap` P3), 0IM transitions from R script to bridge yaml form, but phase sequence semantics unchanged
- Cross-ref `etl-architecture-roadmap` Requirement 2 (P3 scope of 0IM migration)
- Increment `version` from v1.0 to v1.1
